# Contributing

Start with the [project charter](docs/charter.md) and the public contracts. For a change to a module, identify the user-visible behavior, the responsible module and the test that proves it. For a change to an integration event, include a compatibility example for an existing consumer.

Keep a pull request focused on one change. Include the commands you ran and the result you observed. Explain the trade-off when introducing a dependency or changing who owns data. A decision that changes more than one module should identify the affected consumers so they can be reviewed together.

Project discussions cover software architecture, implementation, teaching examples and reproducible bugs. Credit sources and identify the terms of any third-party material you propose to include. The maintainer is [Milan Jovanović](https://github.com/m-jovanovic).
